# 0084. Nothing is mounted from the compose project directory

- **Status:** Accepted
- **Date:** 2026-09-02
- **Area:** Container deployment

## Context

Four failures appeared only on a machine other than the one that wrote the files. (1) A partial node_modules from an interrupted install is not repaired by `npm install`, and the build fails on a missing transitive dependency forever. (2) Quartz removes and recreates its output directory, which a bind mount point forbids (`EACCES: rmdir`). (3) Named volumes are root-owned while every service runs as the host uid; npm failed to write its log directory, an error naming neither ownership nor volumes. (4) The loop script and Caddy config were mounted from the compose project directory, which works in a checkout only. On a machine holding just compose.yml and.env, Docker creates a directory at the missing path and the container dies on 'Permission denied' or 'mount a directory onto a file'.

Running both at once leaves very little free'.

## Decision

(1) A sentinel `node_modules/.gamereg-install-ok` holding the package-lock cksum, written only after a successful install. (2) Quartz builds into its own public/ and the contents are copied to /site. (3) Bind mounts for the site output and the cache, with site-build's HOME=/cache. (4) site-loop.sh is baked into the image and the Caddyfile is generated by site-build into the shared /site directory; nothing is mounted from the project directory. Later, ac65c33 staged the Quartz tree into /cache/quartz-build so the vault mount is: ro.

## Consequences

The site is briefly incomplete while copying. Every rebuild copies the Quartz tree into scratch. The profile stays off by default and is unsuitable for 1 GB machines. No automated test runs site-loop.sh; test/entrypoint-wrapper.test.ts:690 only checks the file exists.
