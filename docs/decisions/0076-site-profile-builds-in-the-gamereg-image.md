# 0076. The site profile builds Quartz in the gamereg image and watches git HEAD

- **Status:** Accepted
- **Date:** 2026-09-01
- **Area:** Site and comments

## Context

Quartz's own Dockerfile runs `npx quartz build --serve`, a development server with no EXPOSE and no production story. ghcr.io/jackyzha0/quartz: hugo is the abandoned v3 line.

(2) Quartz removes and recreates its output directory, which a bind mount point forbids (`EACCES: rmdir`).

Measured: npm install 14s, Quartz build 4s, 2 min from up to page, ~280 MB free with the whole stack.

A CLAUDE_CODE_OAUTH_TOKEN env var plus an anthropic: cli profile authenticates nothing, because the credential lives in a per-agent SQLite auth store; it took two deployments and a third machine. Serving the site: `caddy file-server` alone 404s internal links, and the obvious try_files order is still wrong because Quartz emits both tags/x.html and a tags/x/ directory.

Running both at once leaves very little free'.

## Decision

docker/site-loop.sh, baked into the gamereg image (already Node-based), builds whenever the vault's git HEAD moves. caddy:2-alpine serves the result. No second base image.

(1) A sentinel `node_modules/.gamereg-install-ok` holding the package-lock cksum, written only after a successful install. (2) Quartz builds into its own public/ and the contents are copied to /site. (3) Bind mounts for the site output and the cache, with site-build's HOME=/cache. (4) site-loop.sh is baked into the image and the Caddyfile is generated by site-build into the shared /site directory; nothing is mounted from the project directory. Later, ac65c33 staged the Quartz tree into /cache/quartz-build so the vault mount is: ro.

## Consequences

site-build pulls the whole gamereg image (CLI plus OpenClaw) just for node and npm, and is tied to that image's Node version. The loop watches git HEAD rather than being triggered, so no Docker socket is needed. Reopen if Quartz publishes a production image.

The site is briefly incomplete while copying. Every rebuild copies the Quartz tree into scratch. The profile stays off by default and is unsuitable for 1 GB machines. No automated test runs site-loop.sh; test/entrypoint-wrapper.test.ts:690 only checks the file exists.

A token-file sentinel (.gamereg-auth-seeded) means a changed token needs the sentinel removed.
