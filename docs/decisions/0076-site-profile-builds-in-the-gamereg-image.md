# 0076. The site profile builds Quartz in the gamereg image and watches git HEAD

- **Status:** Accepted
- **Date:** 2026-09-01
- **Area:** Site and comments

## Context

Quartz's own Dockerfile runs `npx quartz build --serve`, a development server with no EXPOSE and no production story. ghcr.io/jackyzha0/quartz:hugo is the abandoned v3 line.

Four failures appeared only on a machine other than the one that wrote the files. (1) A partial node_modules from an interrupted install is not repaired by `npm install`, and the build fails on a missing transitive dependency forever. (2) Quartz removes and recreates its output directory, which a bind mount point forbids (`EACCES: rmdir`). (3) Named volumes are root-owned while every service runs as the host uid; npm failed to write its log directory, an error naming neither ownership nor volumes. (4) The loop script and Caddy config were mounted from the compose project directory, which works in a checkout only. On a machine holding just compose.yml and.env, Docker creates a directory at the missing path and the container dies on 'Permission denied' or 'mount a directory onto a file'.

First: a partial node_modules is not self-healing. Second: Quartz rm/recreates its output dir, which a bind mount point forbids (EACCES: rmdir). Third: named volumes are root-owned while services run as the host uid (symptom: npm cannot write its log dir). Fourth: files mounted from the compose project directory work only in a checkout; on a machine holding only compose.yml and.env, Docker creates a directory and the container dies. Measured: npm install 14s, Quartz build 4s, 2 min from up to page, ~280 MB free with the whole stack.

The agent answered like a stock assistant with no error: the seeded config's ~/.openclaw/workspace resolves beside the state dir in the container, so the persona and skill were not found. A CLAUDE_CODE_OAUTH_TOKEN env var plus an anthropic:cli profile authenticates nothing, because the credential lives in a per-agent SQLite auth store; it took two deployments and a third machine. Model choice had been a side effect of the auth branch. Serving the site: `caddy file-server` alone 404s internal links, and the obvious try_files order is still wrong because Quartz emits both tags/x.html and a tags/x/ directory.

Running both at once leaves very little free'.

## Decision

docker/site-loop.sh, baked into the gamereg image (already Node-based), builds whenever the vault's git HEAD moves. caddy:2-alpine serves the result. No second base image.

(1) A sentinel `node_modules/.gamereg-install-ok` holding the package-lock cksum, written only after a successful install. (2) Quartz builds into its own public/ and the contents are copied to /site. (3) Bind mounts for the site output and the cache, with site-build's HOME=/cache. (4) site-loop.sh is baked into the image and the Caddyfile is generated by site-build into the shared /site directory; nothing is mounted from the project directory. Later, ac65c33 staged the Quartz tree into /cache/quartz-build so the vault mount is:ro.

A post-install sentinel. Build into Quartz's own public/ and copy out. Bind mounts instead of named volumes (except remark42). Bake the loop script into the image, and have site-build write the Caddyfile into the shared dir. Rule: nothing may be mounted from the compose project directory.

Derive the workspace from OPENCLAW_STATE_DIR. Install the token with `openclaw models auth paste-token` at boot. Model selection is its own step (OPENCLAW_MODEL, OPENCLAW_MODEL_FALLBACK). Caddy uses `try_files {path}.html {path}/index.html {path}`. Rule: a credential that is present is not a credential that is installed.

## Consequences

site-build pulls the whole gamereg image (CLI plus OpenClaw) just for node and npm, and is tied to that image's Node version. The loop watches git HEAD rather than being triggered, so no Docker socket is needed. Reopen if Quartz publishes a production image.

The site is briefly incomplete while copying. Every rebuild copies the Quartz tree into scratch. The profile stays off by default and is unsuitable for 1 GB machines. No automated test runs site-loop.sh; test/entrypoint-wrapper.test.ts:690 only checks the file exists.

The measurements are version-bound and stale after the OpenClaw 2026.9.4 upgrade.

A token-file sentinel (.gamereg-auth-seeded) means a changed token needs the sentinel removed. OpenRouter installs choose Anthropic by setting OPENCLAW_MODEL.
